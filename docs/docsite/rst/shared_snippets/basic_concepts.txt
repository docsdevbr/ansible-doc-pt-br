Nó de controle
==============

A máquina a partir da qual você executa as ferramentas CLI do Ansible
(``ansible-playbook``, ``ansible``, ``ansible-vault`` e outras).
Você pode usar qualquer computador que atenda aos requisitos de software como nó
de controle — notebooks, desktops compartilhados e servidores podem executar o
Ansible.
Você também pode executar o Ansible em contêineres conhecidos como
:ref:`Ambientes de execução<getting_started_ee_index>`.

É possível usar vários nós de controle, mas o Ansible em si não coordena entre
eles; consulte ``AAP`` para obter informações sobre esses recursos.

Nós gerenciados
===============

Também chamados de 'hosts', esses são os dispositivos de destino (servidores,
dispositivos de rede ou qualquer computador) que você deseja gerenciar com o
Ansible.

O Ansible normalmente não é instalado em nós gerenciados, a menos que você
esteja usando ``ansible-pull``, mas isso é raro e não é a configuração
recomendada.

Inventário
==========

Uma lista de nós gerenciados fornecida por uma ou mais 'fontes de inventário'.
Seu inventário pode especificar informações específicas para cada nó, como
endereço IP.
Ele também é usado para atribuir grupos, que permitem a seleção de nós no play e
a atribuição em massa de variáveis.

Para saber mais sobre inventário, consulte a seção
:ref:`Trabalhando com inventário<intro_inventory>`.
Às vezes, um arquivo de origem de inventário também é chamado de
'hostfile'.

Playbooks
=========

Eles contêm plays (que são a unidade básica de execução do Ansible).
Este é um 'conceito de execução' e também como descrevemos os arquivos nos quais
o ``ansible-playbook`` opera.

Os playbooks são escritos em YAML e são fáceis de ler, escrever, compartilhar e
entender.
Para saber mais sobre playbooks, consulte :ref:`about_playbooks`.

Plays
-----

O contexto principal para a execução do Ansible, este objeto playbook mapeia nós
gerenciados (hosts) para tarefas.
O play contém variáveis, roles e uma lista ordenada de tarefas e pode ser
executado repetidamente.
Ele consiste basicamente em um loop implícito sobre os hosts e tarefas mapeados
e define como iterar sobre eles.

Roles (Funções)
...............

Uma distribuição limitada de conteúdo Ansible reutilizável (tasks, handlers,
variáveis, plugins, templates e arquivos) para uso em um play.

Para usar qualquer recurso de role, a própria role deve ser importada para o
play.

Tasks (Tarefas)
...............

A definição de uma 'ação' a ser aplicada ao host gerenciado.
Você pode executar uma única tarefa uma vez com um comando ad hoc usando
``ansible`` ou ``ansible-console`` (ambos criam um play virtual).

Handlers
........

Uma forma especial de tarefa, que só é executada quando notificada por uma
tarefa anterior que resultou em um status 'changed'.

Módulos
=======

O código ou binários que o Ansible copia e executa em cada nó gerenciado (quando
necessário) para realizar a ação definida em cada tarefa.

Cada módulo tem um uso específico, desde administrar usuários em um tipo
específico de banco de dados até gerenciar interfaces VLAN em um tipo específico
de dispositivo de rede.

Você pode invocar um único módulo com uma tarefa ou invocar vários módulos
diferentes em um playbook.
Os módulos do Ansible são agrupados em coleções.
Para ter uma ideia de quantas coleções o Ansible inclui, consulte a
:ref:`list_of_collections`.

Plugins
=======

Códigos que expandem as funcionalidades principais do Ansible.
Os plugins podem controlar como você se conecta a um nó gerenciado (plugins de
conexão), manipular dados (plugins de filtro) e até mesmo controlar o que é
exibido no console (plugins de retorno de chamada).

Consulte :ref:`working_with_plugins` para obter detalhes.

Coleções
========

Um formato no qual o conteúdo do Ansible é distribuído, que pode conter
playbooks, roles, módulos e plugins.
Você pode instalar e usar coleções por meio do
`Ansible Galaxy <https://galaxy.ansible.com>`_.

Para saber mais sobre coleções, consulte :ref:`collections`.

Os recursos de coleção podem ser usados de forma independente e discreta uns dos
outros.
